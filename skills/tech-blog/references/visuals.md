# 시각화 제작·검증 기준

본문의 주장을 가장 쉽게 검증하고 이해할 수 있는 형식을 선택한다. 모든 글에 정해진 개수의 이미지를 넣을 필요는 없다. 핵심 수치와 구조가 글로만 남아 있는지를 기준으로 판단한다.

## 정보의 범위와 밀도

- 한 그림은 하나의 핵심 비교나 관계에 집중한다. 제목, 요소 이름, 값·단위, 축·범례, 연결 관계처럼 시각화한 정보를 읽는 데 필요한 내용만 짧게 넣는다.
- 배경 설명, 결론 문단, 주의사항 상자, 출처·작성자·날짜 등의 부가 정보는 그림 밖 본문에 둔다. 조건 자체를 비교하는 그림이라면 해당 조건을 짧은 레이블로 표시한다.
- 예를 들어 작업 시작 시간 비교 그림에는 비교 대상과 시간·단위만 담는다. 측정 환경, 개선 이유, 첫 작업의 예외, 적용 시 주의점은 본문에서 설명한다.

## 표현 선택

- 전후 지연 시간·처리량·비용 비교는 막대나 점 그래프를 쓴다. 추이는 선 그래프, 구성 비중은 누적 막대, 반복 측정의 퍼짐은 범위·분포로 보여 준다.
- 소유 관계와 의존성은 구조도, 요청과 메시지 전달은 흐름도·시퀀스도, 프로세스 생성과 종료는 수명선이나 타임라인을 쓴다.
- 선택지별 속성은 표로 비교할 수 있다. 수치의 크기 차이나 실행 경로를 설명해야 할 때는 표에 차트나 도식을 더한다.
- 같은 대상을 여러 그림에서 다루면 이름·색·방향을 유지한다. 하나의 그림에서 다루기 어려운 정보는 개념별로 나눈다.

## 수치의 정직성

- 그림에는 단위, 축, 필요한 범례를 명시하고 측정 조건은 본문에 적는다. cold/warm이나 초기화/전체 처리처럼 값의 의미를 구별하는 표기는 그림에도 짧게 남긴다. 서로 다른 측정 범위를 섞지 않는다.
- 반복 측정 자료가 있으면 표본 수와 요약 방식을 본문에 밝히고, 범위·분포는 필요한 경우 시각화한다. 자료에 없는 표본 수나 오차 막대를 만들지 않는다.
- 막대의 길이로 값을 비교할 때는 0 기준을 사용한다. 로그 축, 축 절단, 크기와 비례하지 않는 표현은 그림에서 식별할 수 있게 표시하고 이유와 읽는 방법은 본문에서 설명한다.
- 차이가 매우 커 작은 값이 안 보이면 값 라벨이나 별도 확대 영역을 추가한다. 개선 배수와 감소율은 원자료로 계산하고 분모를 분명히 한다.
- 도식용 예시 값은 '예시'라고 표시한다. 예시를 실측 결과처럼 회고나 제목에 사용하지 않는다.

## 구조의 정확성

- 상자에는 구성 요소의 역할을, 화살표에는 호출·메시지·데이터 등 관계의 의미를 적는다. 프로세스 경계와 통신 경로가 중요한 글이면 그림에서도 경계를 구별한다.
- 전후 도식에는 변경 지점을 표시한다. 개념 설명을 위한 생략은 캡션에 밝히고, 핵심 동작을 바꾸는 단순화는 피한다.
- 실제 코드나 자료에 없는 연결과 실행 주체를 추가하지 않는다. 그림에서도 확인된 구조와 제안한 구조를 구별한다.

## 제작과 전달

- 수치 차트는 데이터로 생성하는 플로팅 도구를, 정확한 레이블과 관계가 중요한 도식은 Mermaid·SVG·HTML 등 편집 가능한 표현을 우선 검토한다. 도구는 현재 환경과 전달 매체에 맞게 고른다.
- 이미지 생성 도구는 개념 일러스트에 유용하다. 사용자가 도구를 지정하면 가능한 범위에서 따르고, 정확한 수치·코드·화살표·한글 레이블은 별도로 검증하거나 편집 가능한 요소로 보완한다.
- 인터랙션이 이해를 돕고 매체가 지원하면 대화형 시각화를 쓴다. 공유·게시용 문서에는 본문만 열어도 읽을 수 있는 정적 버전도 포함한다.
- 게시 대상이 Mermaid나 SVG를 지원하지 않으면 지원되는 이미지 형식으로 렌더링한다. 재편집 가능한 원본도 보존한다. PNG로 내보낼 때는 실제 본문 폭에서 글자가 선명하게 읽히도록 한다.
- 각 그림에 의미 있는 대체 텍스트와 짧은 캡션을 제공한다. 핵심 차이는 색뿐 아니라 레이블·모양으로도 구별한다.
- 렌더링 결과를 직접 열어 한글 깨짐, 잘림, 겹침, 화살표 방향, 대비와 모바일 폭 가독성을 확인한다. 그림 안의 문구는 대상 정보를 읽는 데 필요한 것만 남긴다. 생성된 코드나 파일 존재만으로 검증을 끝내지 않는다.
- 위키나 블로그에 게시할 때는 로컬 절대 경로를 독자가 접근 가능한 첨부 주소로 바꾼다. 게시본에서 이미지가 실제로 로드되는지 확인한다. 업로드가 실패하면 본문과 원본 이미지를 보존하고 실패 지점을 보고한다.
